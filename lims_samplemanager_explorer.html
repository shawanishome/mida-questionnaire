🎭 Roles vs Groups

Roles control what functionality a user can access — menu items, actions, features.

Groups control what data a user can see — e.g. Microbiology group only sees micro samples.
📋

SampleManager Administrator Responsibilities
👥

User & Operator Management

Create operator records in PERSONNEL table; assign passwords to grant system access; configure roles and groups per person.

🎭

Role & Group Configuration

Define roles mapping menu items to access levels; assign lab units (e.g. Microbiology, Chemistry) as groups to control data visibility.

🖨️

Printer Definitions

Map OS-defined printers into SampleManager so reports can be generated and directed to the correct physical or network printers.

⚙️

Background Services

Configure and manage the watchdog Windows service that runs VGL programs and .NET tasks in non-interactive (background) mode.

💾

Backups & Data Maintenance

Design and verify backup strategies for the database and folder tree. Move data between active, committed, and archive tables to maintain performance.

🗂️

File & Folder Cleanup

Remove VGL dump files, stale log files, orphaned text files. Keeps disk usage lean and OS performance high.

🎓

Training Course Tracking

Link training records to operators; gate critical tasks (result entry, instrument prep) so only qualified personnel can perform them.

🔄

Version Upgrades

Plan and execute upgrades every ~16 months. Always test on a copy first; validate standard and custom functionality before production rollout.

🌐

Localization & Config Items

Modify language/message files for industry-specific terms; set configuration items at System, Group, or User level to tailor the operating environment.

📋

Audit & Compliance

Oversee audit trail configuration and electronic signature setup for 21 CFR Part 11 and other regulatory compliance requirements.

Supported Database Engines
🔴
Oracle
Enterprise relational DB
Tablespace & user auto-created during install
SYS password needed to create new accounts
Existing tablespace can be reused
Connection string written to Windows registry
Most common for large regulated labs
🐘
PostgreSQL
Open-source relational DB
Server and database selected in wizard
No SYS-equivalent needed for setup
Lightweight deployment option
Connection string stored in registry
Growing support in newer SM versions
🪟
SQL Server
Microsoft relational DB
SQL Server instance selected in wizard
Supports Windows integrated authentication
Database auto-created if SYS-equivalent given
Strong choice for Windows-centric environments
Connection string configurable post-install
📊
Data Tables
Active / Committed / Archive
Active: current in-progress jobs & samples
Committed: completed data kept online
Archive: offloaded to external storage
structure.txt defines custom table schema
Indexes & views configurable by admin
SYSTEM User & Default State
⚠️ On fresh install, a SYSTEM user is created with a blank password. Thermo Fisher recommends setting this password immediately post-installation. The SYSTEM user can login once without a license. Any user-specific changes (default printer, group settings) should be applied before going live.
Installation Sequence — Server & Client
SERVER INSTALL
1
Verify database engine Oracle, PostgreSQL, or SQL Server must be ready
2
Mount .iso & run setup.exe Manual or autorun install wizard
3
Install Thermo Licensing Service License server can be collocated or separate
4
Create Server Instance Wizard Name, DB selection, connection string
5
Build database schema Creates SM tables, loads default data
6
Compile VGL programs All VGL source compiled on first run
7
Configure network & services Add Windows services, port 56100 default
8
Site-specific setup Load .NET forms, add licensing, set SYSTEM password
CLIENT INSTALL OPTIONS
🖥 Desktop (MSI)
Windows Installer Package; full-featured client; connects to server by IP/hostname + port
🌐 Web Client (IIS)
Installed on Windows 2019 IIS; Chrome/Edge; run WebClient_Setup.exe; synchronize resources post-setup
🏛 Portal Client (IIS + MongoDB)
Requires .NET hosting + MongoDB 4.2.5; appsettings.json config; default port 9011; HTTPS required for SSO
📱 Mobile App (WCF)
WCF Services must be enabled; app installed on mobile device; connects to server over network
STARTUP SEQUENCE
Login prompt → Validate credentials → Load config → Sync resource folder → Load menu & toolbars → Execute background checks → Ready ✓
